# TMate 数据口径与接口

## 数据口径

- 行程净耗电无法计算时，`energy.netUnavailable` 返回 `no-efficiency`（缺少有效车辆能耗系数）或 `no-range`（缺少起止额定续航），界面显示相应原因；不会套用其他车型系数或编造耗电。计算正常时为 null。
- 所有日期按 `Asia/Shanghai` 显示；统计范围包括今天在内的最近 7 / 30 / 90 个自然日。
- 统计仅包含完成的行程和充电。正在行驶、充电等状态由 MQTT 提供；当前进行中的记录不会计入已完成记录合计。
- 耗电估算 = `(start_rated_range_km - end_rated_range_km) × cars.efficiency`。平均能耗按有有效估算值的行程里程加权。缺少系数时显示 `—`；净回收能量可能为负。
- 行程详情「能量」展示净耗电量（kWh）、平均净能耗（kWh/100 km，同时给出 Wh/km）与有效片段内的动能回收估算。净耗电已包含回收的影响，不再次扣除回收值；净耗电为负时保留负值。它们不是电表实测值。
- 动能回收先在服务端读取本车、本次已完成行程时间内的原始功率采样，再对相邻有效采样的负功率部分做线性积分；跨越零功率时只计负值区间。时间差必须大于 0 且不超过 1.5 秒，不跨越空功率、重复时刻或长时间断点；使用完整秒数，不对分钟取余。未收到功率或采样过稀时返回 `null` 并说明原因，不以 0 代替。只有有效区间确实未出现负功率时才可返回 0。
- 回收覆盖率 = 有效连续功率区间总秒数 / 本次行程时长。只展示「动能回收 · 有效片段」，不把局部记录冒充整段行程的完整回收电量。不从抽样后的地图或曲线反算能量；与 Grafana 的负功率点筛选/积分方法可能略有差异。
- 行程电池曲线包含电量 SOC、可用电量、额定续航、预估续航及电池加热开关。独立于 GPS：无定位也能展示已有电池采样；可选列不存在时只缺失对应曲线。按各传感器独立抽样，每项最多 1002 点，保留各自首末记录；不因密集电量采样丢掉稀疏的加热或续航记录。时间轴按真实时间绘制，超过 3 分钟没有该项记录的区间断开，单点保留为点。首末电量指首末有效采样，不冒充精确出发/结束时刻，也不是电池 SOH。
- 充电费用优先读取 TeslaMate 的 `cost`（包含真实的 0 元）。在设置保存电费单价后，只补算 `cost` 缺失的记录：优先用电网用电量 × 单价，电网量无效时用充入电量 × 单价，标明「估算」。数据均缺失时仍显示未记录。单价留空关闭估算，0 表示按 0 估算；最多 4 位小数，范围 0–1000。
- 单价是当前设备的显示偏好，不同步到其他设备，不写入 TeslaMate；更改单价会重新估算历史缺费记录，不代表分时电价或真实账单。货币设置只改变符号。合计使用整个统计范围的后端聚合，不只计算前 50 条；旧后端缺少新聚合字段时会明确提示升级，不展示不完整的估算总额。
- 满电续航估算取充电结束电量 ≥ 50% 的记录，使用 `end_rated_range_km / end_battery_level × 100`，同日取平均。这不是电池 SOH 检测值。
- PostgreSQL 的最新行驶位置与最新充电采样按时间比较，电量和续航使用较新的记录。
- 位置取本车最后一组有效经纬度；四轮胎压分别取本车各轮最后一次有效采样，单位 bar。新记录的空值不覆盖历史有效值，数值 0 不当作缺失；此查询不受 7 / 30 / 90 天统计区间限制。兼容没有 TPMS 列的旧数据库，不修改表结构。
- 概览显示已记录坐标，不自动请求外部地图或反向地理编码。位置与每个轮胎标注各自数据库采样时间，不借用电量更新时间；历史记录不代表车辆此刻的位置或胎压。
- 收到有效 MQTT `location`（JSON 经纬度，兼容旧 latitude / longitude 主题）或胎压时，仅覆盖相应字段，标为「MQTT · 测量时间未提供」。只有围栏名称而没有 MQTT 坐标时，不混用历史坐标。
- MQTT retained 消息不含原始测量时间。因此页面提示可能为最后保留值，不把订阅接收时间当作车辆测量时间。断开 MQTT 后回退到数据库历史记录。
- 软件版本：优先有效 MQTT 上报；否则读取 `updates` 表本车最近一次已完成升级（未完成升级不计入）。无表/无权限时仅此字段回退，不导致整个车辆面板失败，并提示原因。
- 哨兵模式不保存在 TeslaMate 的位置历史中，不能通过数据库编造开关状态。TMate 会保存收到的 `version` 和 `sentry_mode` 及接收时间（不是测量时间），断线/重启后显示「最近已知状态」。从未收到时显示「尚未收到」，不是关闭。缓存最长 30 天，最多 100 辆车，位于 `MAP_CACHE_DIR/vehicle-status.json`，权限 600；仅这两项，不保存额外轨迹。未设置缓存目录或磁盘不可写时只在内存保留，重启丢失。
- 轨迹与曲线会抽样以控制手机数据量。行程地图使用受鉴权保护的高德静态底图，支持缩放、全程、起点和终点视图，暂不支持拖动平移；WGS-84 采样在本地转换成 GCJ-02 后叠加，原始采样不变，不是导航规划路线。
- 配置高德后优先使用实际行程起终点采样（缺失时使用已有地址坐标）解析中文详细地址，自定义围栏作为前缀保留。只有最近道路时明确显示距道路的估算距离，不编造门牌或道路名称。首次解析异步排队，页面正常刷新后使用缓存；服务失败或没有道路信息时回退已有中文地名/原文，并返回 `unresolved` 精度标记，不保证所有农村或无名道路均有精确门牌。完整地理编码原始信息和 Key 不下发到网页，也不改写 TeslaMate 数据。

## 接口

下列车辆数据接口只允许 GET，需要 `Authorization: Bearer <API_KEY>` 或有效的同源设备会话。`GET /api/health` 和 `GET /api/session` 仅返回公共服务/授权状态，不返回车辆数据。

| 接口                                              | 内容                             |
| ------------------------------------------------- | -------------------------------- |
| `/api/cars`                                       | 车辆列表                         |
| `/api/cars/:id/dashboard?days=30`                 | 车辆概览、全量汇总、前 50 条记录 |
| `/api/cars/:id/drives?days=30&offset=0&limit=30`  | 行程分页，最多每页 100 条        |
| `/api/cars/:id/charges?days=30&offset=0&limit=30` | 充电分页                         |
| `/api/cars/:id/drives/:driveId/track`             | 轨迹与速度采样，检查车辆归属     |
| `/api/cars/:id/drives/:driveId/detail`            | 行程能量与电池曲线，只返回本车已完成行程；不存在/跨车辆/未结束返回 404 |
| `/api/cars/:id/drives/:driveId/map?focus=route&zoom=0` | 高德底图与本地轨迹，focus 可选 start/end，zoom 为 -2 至 4 的相对级别 |
| `/api/cars/:id/charges/:chargeId/curve`           | 充电采样，检查车辆归属           |

连接池默认只读，查询参数化并设置 15 秒超时。还应使用独立 SELECT-only 数据库账号。API 不会返回数据库连接串或访问密钥。

行程详情返回 `{ energy, battery }`。`energy` 包含 `netKwh`、`consumptionKwh100Km`、`recoveredKwh`、`recoveryCoverage`（0–1 或 null）、`recoveryUnavailable`（`no-power` / `sparse-power` / null）。`battery.series` 的键为 `battery`、`usableBattery`、`ratedRange`、`estimatedRange`、`heater`，每项是 `{date,value}[]`，日期为 UTC ISO 字符串；加热值为 0/1。`battery.sampleCounts` 给出每项抽样前的有效记录数。新端点不返回坐标，不调用高德，不增加数据库写权限；旧轨迹、地图与充电接口保持兼容。

设备授权另有 `POST /api/pairings`（仅服务密钥可生成链接）、`POST /api/session`（同源配对或密钥交换）与 `DELETE /api/session`（退出当前浏览器）。这些接口不修改 TeslaMate 数据。配对接口校验来源、请求体格式与大小；会话验证签名与有效期。
